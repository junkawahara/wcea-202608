# IQ Flow ソルバー

SmartGames「IQ Flow」(Raf Peeters 作、2026 年発売、SG 340)のソルバー。
Node.js のみで動作(依存パッケージなし)。

IQ Flow は 5×5 グリッドを 8 ピースで埋めるパッキングパズルだが、
ピースを上から置くことができず、**盤の縁の開口部から波の方向にスライドさせて
入れる**ことしかできない。問題は初期配置ではなく**最終配置(の一部)**を示し、
そこに至る挿入順序・退避操作を見つけるのがプレイヤーの仕事になる。

## 使い方

```bash
node iqflow.js                                  # 内蔵の公式例題(STARTER)を解く
node iqflow.js challenges/starter-example.json  # JSON の問題を解く
node iqflow.js challenges/expert-example.json   # EXPERT 形式(波の向きのみ)の問題
node iqflow.js --keep D,G                       # Master/Wizard 級の再現(ヒントを D,G だけに間引く)
node iqflow.js --enumerate                      # 最短手順を全列挙(件数+一覧、100 件まで)
node iqflow.js --steps                          # 1 手ごとの盤面を表示
node iqflow.js --first                          # 実現可能な配置が 1 つ見つかった時点で打ち切り
node analyze.js                                 # 全 18,128 パッキングの実現可能性を全数調査
```

プログラムからは `require('./iqflow.js')` で
`solveChallenge / solveOrdering / enumerateOptimal / completePackings /
goalsFromRegions / staticFeasible` などが使える。

## 問題ファイルの形式

座標は `[行, 列]`、左上が `[0,0]`。行は下向き、列は右向きに増える。

通常の問題(STARTER〜WIZARD)。`goal` に載せたピースだけがヒントになり、
残りのピースの置き方はソルバーがパッキング列挙で探す:

```json
{
  "name": "問題名",
  "goal": {
    "A": [[0,0],[0,1]],
    "F": [[1,0],[1,1],[1,2],[2,0]]
  }
}
```

EXPERT 形式(領域の形と波の向きだけが与えられ、どのピースかは伏せられている):

```json
{
  "name": "問題名",
  "regions": [
    { "cells": [[0,0],[0,1]], "axis": "v" },
    { "cells": [[0,2],[0,3]], "axis": "h" }
  ]
}
```

`officialSolution` に `"B→ A↑ F← D← H↑ G↑ C→ E→"` 形式の手順を書いておくと、
解いたあとにその手順の合法性を検証する。

## ゲームデータ(公式資料から読み取り)

### ピース(8 個、計 25 マス)

`axis` は基準の向きでの滑り軸(`h`=左右、`v`=上下)。**波はピースに固定**で、
挿入前の回転(90°単位)で形と軸が一緒に回る。裏返しは物理的に不可。
盤上では回転できないため、挿入時の向き = 最終的な向き。

| ID | 色 | 形(基準の向き) | 滑り軸 |
|----|------|-------------------|--------|
| A | ピンク | `AA`(ドミノ) | v(長軸と直交!) |
| B | 赤 | `BB`(ドミノ) | h |
| C | 紫 | `CCC`(I トロミノ) | h |
| D | 黄 | `DD` / `.D`(L トロミノ) | h |
| E | 橙 | `EE` / `E.`(L トロミノ、D の鏡像) | h |
| F | 緑 | `FFF` / `F..`(J テトロミノ) | h |
| G | 水色 | `G.` / `GG` / `.G`(S テトロミノ) | v |
| H | 紺 | `.H` / `HH` / `.H`(T テトロミノ) | v |

### 盤面の開口部

上辺は蓋のヒンジで全閉。他 3 辺も開いている区間は一部のみ:

```
      # # # # # # #        # = 壁(挿入不可)
   0  : . . . . . #        : = 開口部
   1  # . . . . . :
   2  # . . . . . :        左辺: 行 0, 3, 4
   3  : . . . . . :        右辺: 行 1, 2, 3
   4  : . . . . . #        下辺: 列 0, 1, 3, 4
      # : : # : : #
```

ピースは 5×5 の外周(リング、深さ 1 マスと仮定)に一時退避でき、
開口部から盤外へ抜くこともできるが、完成形では全ピースが 5×5 内に収まる。

### データの出典と検証

- ピース形状・波の向き: 公式例題の完成図と公式の完成状態俯瞰写真
  (SG340_IQ-Flow_image_step3_web.jpg)の 2 つの独立な盤面から相互検証。
- 開口部: 公式の空盤面俯瞰写真(step1)から読み取り。
- 総合検証: 公式例題の解答手順「B→ A↑ F← D← H↑ G↑ C→ E→」がこのモデルで
  合法手順であることを確認。さらにこの例題の最短 8 手手順は**この 1 通りしかない**
  (B<A<F<D<H<G<C<E の全順序が強制される)ことも確認した。
- ルール文: 公式ルールリーフレット(設計者 Raf Peeters のサイトに全文掲載)。
  <https://www.smartgamesandpuzzles.com/iq-flow.html>

実物との照合が済んでいない仮定: リングの深さ(1 マスとした)、
「リングからさらにはみ出した位置で静止はできない」、
「一時的に最終と異なる向きで挿入して後で抜く戦略は使わない」の 3 点。
市販の問題で解が見つからないケースが出たら、まずここを疑うこと。

## アルゴリズム

1. **パッキング列挙**: ヒントにないピースの置き方を exact cover の DFS で全列挙
   (ヒントなしなら 18,128 通り)。
2. **静的枝刈り**: 各ピースの占有帯(横滑りなら行の集合、縦滑りなら列の集合)が
   いずれかの辺の開口部に完全に含まれていない配置は、その場で棄却。
3. **順序探索**: 残った配置ごとに BFS。ピースの向きと(滑り軸と直交方向の)位置は
   挿入時に確定して以後不変なので、状態は「各ピースが手元にあるか、軸方向に
   d ずらした位置にいるか」だけで表せる(8 ピース × 高々十数状態 → 32bit キー)。
   手は「挿入(開口部から経路が空いていれば任意の位置に停止可)」
   「盤上スライド」「盤外へ抜く」の 3 種。BFS なので最短手数が得られる。
4. **数え上げ**(`--enumerate`): 最短手数を求めたあと、
   「深さ + 未完了ピース数 ≦ 最短手数」で枝刈りした層別 BFS で最短経路 DAG を
   作り、DP で本数を数える。

計算量の目安: 1 配置の順序判定が約 0.2 秒、全 18,128 配置の全数調査が数分。
